# Проектирование системы умного дома: Мобильное приложение «Stets Home»

## Описание и цель проекта
Спроектировать комплексную архитектуру мобильного приложения для управления умным домом **«Stets Home»** — от анализа потоков данных и проектирования реляционной базы данных до создания интерактивного прототипа в Figma и разработки программы испытаний (ПМИ).
**Стек и инструменты:** DFD (Yourdon-DeMarco), ER-моделирование (3НФ, Crow's Foot), Data Dictionary, QA / ПМИ, Figma, Draw.io, MS Word, Markdown.

## Проработанные артефакты
* **Диаграммы потоков данных (`DFD.drawio`):**
  * **Контекстная диаграмма (DFD Level 0):** взаимодействие мобильного приложения с внешними сущностями (*Пользователь*, *Сервер Stets Home*, *Производитель устройств*, *Сторонние сервисы*).
  * **Детализированная диаграмма (DFD Level 1):** декомпозиция на 7 ключевых процессов (управление аккаунтом, доступом к дому, устройствами, комнатами, сценариями и уведомлениями) и 7 хранилищ данных (`D1`–`D7`).
* **Модель базы данных (`ERD.drawio`):** логическая ER-диаграмма в третьей нормальной форме (3НФ), включающая 11 сущностей (`Пользователь`, `Доступ к дому`, `Дом`, `Комната`, `Тип комнаты`, `Устройство`, `Тип устройства`, `Сценарий`, `Устройство в сценарии`, `День недели в сценарии`, `День недели`) со связями, первичными (PK) и внешними (FK) ключами.
* **Словарь данных (`словарь.docx`):** формализованное описание сущностей, атрибутов, типов данных (`BIGINT`, `VARCHAR`, `TIMESTAMP`, `BOOLEAN`), длины полей и допустимых значений.
* **Программа и методика испытаний (`ПМИ Stets Home.docx`):** набор тестовых сценариев для проверки соответствия прототипа требованиям ТЗ (`TR-1` – `TR-6`: регистрация, ролевой доступ к дому, добавление устройств по QR-коду/серийному номеру, управление комнатами и сценариями по расписанию/таймеру).
* **Прототип интерфейса (`figma.docx`):** интерактивный прототип мобильного приложения в Figma — [открыть макет в Figma](https://www.figma.com/design/yrW1xtWw73i01sGmHb05qY/%D0%9F%D1%80%D0%BE%D1%82%D0%BE%D1%82%D0%B8%D0%BF-%D0%BF%D1%80%D0%B8%D0%BB%D0%BE%D0%B6%D0%B5%D0%BD%D0%B8%D1%8F-Stets-Home?node-id=4-581&t=nNRddqKixTwNl6OS-1).

## Выводы и результаты проекта
* **Обеспечена полная сквозная трассируемость:** функциональные требования (`TR-1` – `TR-6`), процессы DFD, таблицы базы данных в 3НФ, словарь данных и тест-кейсы ПМИ полностью согласованы между собой.
* **Масштабируемая архитектура данных:** выделение справочников типов комнат/устройств и ассоциативных таблиц для сценариев автоматизации позволяет легко добавлять новые типы IoT-устройств и сложные расписания без перестройки структуры БД.
* **Готовность к передаче в разработку и QA:** наличие интерактивного прототипа в Figma и детализированной методики испытаний минимизирует риски недопонимания между аналитикой, разработкой и тестированием.

## Как открыть файлы проекта
* **Прототип интерфейса:** перейдите по [прямой ссылке в Figma](https://www.figma.com/design/yrW1xtWw73i01sGmHb05qY/%D0%9F%D1%80%D0%BE%D1%82%D0%BE%D1%82%D0%B8%D0%BF-%D0%BF%D1%80%D0%B8%D0%BB%D0%BE%D0%B6%D0%B5%D0%BD%D0%B8%D1%8F-Stets-Home?node-id=4-581&t=nNRddqKixTwNl6OS-1) прямо в браузере.
* **Схемы (`DFD.drawio`, `ERD.drawio`):** скачайте файлы и откройте их через бесплатный онлайн-редактор [app.diagrams.net](https://diagrams.net) (*File -> Open from -> Device*) или в десктопном приложении Draw.io.
* **Документы (`ПМИ Stets Home.docx`, `словарь.docx`, `figma.docx`):** скачайте файлы из репозитория и откройте в Microsoft Word, Google Docs или LibreOffice Writer.

## Структура репозитория
* `DFD.drawio` — контекстная и логическая диаграммы потоков данных.
* `ERD.drawio` — реляционная модель базы данных в 3НФ.
* `словарь.docx` — словарь данных с описанием атрибутов и типов.
* `ПМИ Stets Home.docx` — программа и методика испытаний по требованиям ТЗ.
* `figma.docx` — файл со ссылкой на интерактивный прототип в Figma.
* `README.md` — описание проекта, выводы и навигация.
